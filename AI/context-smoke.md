# Fresh context comprehension smoke

This is a reproducible read-only procedure, not proof that Codex Cloud was invoked.
No native Cloud launch tool is assumed. If unavailable, report NOT RUN; do not quietly
substitute another coding agent, background service or local model. Local link checks
prove navigation integrity only, not model comprehension or skill discovery.

## Run at the exact PR head

1. Create a fresh Cloud task on this repository at the PR SHA, with no prior chat or
   sibling checkout. Capture repository, SHA, tool availability and clean git status.
2. Send the prompt below. Inspect the actual read/tool trace, not merely claimed reads.
3. Require the answer/evidence matrix, no file edits, remote writes, merge/deploy or
   live access. Compare git status before/after; record task URL/transcript and each
   case PASS/FAIL/NOT RUN in the PR. A fresh read-only session, not the implementation
   session, is required to claim this smoke passed.

```text
Read-only comprehension smoke. Start at AGENTS.md, follow task-relevant links and
inspect current instructions/contracts/commands without editing files or making
remote writes. Do not read historical archives unless tracing a specific old claim.
For each case give the minimum reading set, exact file/section evidence, checks,
docs impact and authorization boundary:
A. A small fix restoring an existing invariant without API or durable-rule changes.
B. An optional schema-v1 numeric field must preserve unknown versus explicit zero.
C. A shared API change affects backend and frontend; identify spec/contract owners,
   generated-type delivery, separate PRs and compatibility/version-pair evidence.
D. Someone asks to deploy a green PR to production without merge/QA authorization.
Also identify commands/prerequisites for docs-only versus application changes.
Report policy/code/contract contradictions rather than choosing silently. End with
files actually read, unverified prerequisites and git status. Do not implement.
```

## Expected answers

| Case | Evidence / boundary |
| --- | --- |
| A | Workflow docs-by-exception: zero evergreen-doc changes is valid; tests still cover changed behavior; PR holds evidence |
| B | Product + database/typed schema + relevant decisions/tests; zero differs from unknown, no arbitrary map or silent schema reinterpretation |
| C | One owning Issue; backend OpenAPI first, FE exact committed copy/regenerated types, linked independent PRs, exact compatible SHA pair |
| D | CI is not release approval; no unmerged feature production SHA; backend manual coordinator, explicit staging/merge/production gates and coherent media backup |
| Checks | Testing doc contains docs/skill commands, full Go/PostgreSQL/race/native ARM64 prerequisites; missing tooling is not PASS |

No case should require the old POC roadmap, a phase README, all six skills or all
AI files. [Engineering skills](engineering-skills.md) has a separate catalog-discovery
smoke; manual SKILL.md reads are not evidence of automatic discovery.
